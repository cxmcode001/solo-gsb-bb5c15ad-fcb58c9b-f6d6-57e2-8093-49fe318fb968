# 乐谱反复段展开工具

供排练使用的 Web 应用：逐行输入小节编号与反复记号，自动校验并展开为实际演奏顺序，
页面展示演奏序号、原小节编号、源行号和每次演奏的起止时间（毫秒），并可下载同内容的 CSV；
还支持按起止毫秒查询时间窗内的节拍点（时间、演奏序号、原小节编号、拍序、首拍标记），
以及按起止原谱小节编号定位该源谱范围在实际演奏中每次被完整、连续奏出的片段
（起止演奏序号、起止毫秒与时长）。
可另附多行“演奏序号=BPM”的临时变速方案，展开、节拍点查询与片段定位共用同一速度轨迹。
页面内置实时节拍器：以当前乐谱和临时变速方案从头播放节拍，
首拍高音、其余拍低音，播放到曲终自动停止。
还可一键导出节拍 MIDI（`.mid` 附件，单轨 SMF 格式 0），
每小节首拍与其余拍分别使用第 10 通道的 76、77 号音符，供音乐软件离线使用。

## 启动

一条命令完成构建并启动（构建镜像并安装 `requirements.txt` 中的依赖，随后启动应用）：

```bash
docker compose up --build
```

容器启动时会自动安装依赖（`pip install -r requirements.txt`）并启动应用，无需手动初始化。
本地不使用 Docker 时同样是一条命令启动（见文末“本地开发”）。

## 访问

- 网页：浏览器打开 <http://localhost:5000>
- API：同样经由 5000 端口访问
  - `POST http://localhost:5000/api/expand`，请求体 `{"input": "小节编号逐行文本", "tempo": "可选的临时变速方案"}`
  - `POST http://localhost:5000/api/beats`，请求体 `{"input": "...", "start_ms": 0, "end_ms": 1000, "tempo": "可选的临时变速方案"}`
  - `POST http://localhost:5000/api/segments`，请求体 `{"input": "...", "start_num": 3, "end_num": 7, "tempo": "可选的临时变速方案"}`
  - `POST http://localhost:5000/api/midi`，请求体同上只取 `input`、`tempo` 两个字段，
    成功时返回 `metronome.mid` 文件附件，校验失败时返回 400 与 JSON 错误（见下文“节拍 MIDI 导出”）

MIDI 导出示例（`curl`，`-OJ` 按服务端文件名保存附件）：

```bash
curl -X POST http://localhost:5000/api/midi \
  -H "Content-Type: application/json" \
  -d '{"input": "1[4@120]\n2\n|:3\n4:|x2", "tempo": "3=90"}' \
  -OJ
```

`tempo` 为可选字段：多行文本，每行一条 `演奏序号=BPM`（见下文“临时变速方案”）；
省略或留空时按原谱速度计算。

`/api/segments` 返回 `{"ok": true, "count": 片段数, "pattern": 源谱范围编号序列,
"segments": [{"start_seq", "end_seq", "start_ms", "end_ms", "duration_ms"}, ...]}`；
无匹配时 `count` 为 0、`segments` 为空数组。

## 配置

| 环境变量 | 默认值 | 说明 |
| -------- | ------ | ---- |
| `PORT`   | `5000` | 应用监听端口（修改后请同步调整 compose 的端口映射） |

## 输入格式

每行一个小节编号：

- 编号前加 `|:` 表示反复起点
- 编号后加 `:|xN` 表示反复终点，`N` 为重复次数（2~9）
- 反复段允许嵌套；空行会被忽略
- 行末可附时间标记 `[拍数@BPM]` 或 `[拍数]`：
  - 只写 `[拍数]` 时不切换速度；完全不写标记时拍数默认为 4
  - 带速度的小节在每次演奏到时先切换速度，再累计时长
  - 未标速度的小节沿用上一演奏小节的速度，初始速度为 120 BPM
  - 拍数与 BPM 必须为正整数

示例：

```
1[4@120]
2
|:3
4[2]
|:5
6:|x3
7:|x2[4@90]
8
```

展开结果：`1 2 3 4 5 6 5 6 5 6 7 3 4 5 6 5 6 5 6 7 8`（共 21 小节）。

## 排练时间轴

每个演奏到的小节按 `拍数 × 60 / BPM` 秒累计时长，时间轴从 0 开始；
结果中每个小节的起止时间单位为毫秒，累计时保留完整精度，输出时四舍五入到最近毫秒。
上例前 10 个演奏小节为 120 BPM，第 11 个（小节 7）起切换为 90 BPM，总时长 47000 毫秒。

## 临时变速方案

在小节输入下方的“临时变速”框中，每行填写一条 `演奏序号=BPM`，
展开、节拍点查询与片段定位共用该方案（即同一速度轨迹）：

- 演奏序号按反复展开后的实际轮次计数（从 1 开始），BPM 为正整数
- 演奏到指定轮次时，临时速度优先于该小节的原谱速度，并继续传给后续未标速小节
- 遇到下一处原谱显式速度或下一条临时变速时重新切换
- 空行会被忽略；序号重复、超出展开范围或格式错误时，
  返回的错误会标注“临时变速”及方案内的行号

例如对上例使用方案：

```
11=100
16=60
```

则第 11 轮（小节 7）临时切换为 100 BPM（覆盖原谱的 90 BPM），
第 16 轮（小节 5）起再切换为 60 BPM；第 20 轮再次演奏到小节 7 时，
遇原谱显式速度 90 BPM 重新切换并沿用至曲终，总时长 51133 毫秒。

## 节拍点查询

在展开结果下方输入起止毫秒，即可列出时间窗内的每个拍点：
时间（毫秒）、演奏序号、原小节编号、拍序与首拍标记。

- 时间窗按左闭右开 `[起始, 结束)` 处理
- 落窗判断使用未取整的累计时间，展示毫秒仍四舍五入到最近毫秒
- 反复回跳后，未标 BPM 的小节沿用上一实际演奏小节的速度
- 查询按小节跨度跳过窗外拍点；窗内拍点超过 5000 时停止并指出对应源行

## 排练片段定位

在页面底部输入起止原谱小节编号，即可列出该源谱范围在实际演奏中
每次被完整、连续奏出的片段：起止演奏序号、起止毫秒与时长（毫秒）。

- 范围按源谱输入顺序确定：从起点编号到终点编号之间的源谱小节序列即为匹配模式；
  两个端点都必须存在于源谱，且起点在源谱输入顺序中的位置不得晚于终点
- 一次匹配必须逐小节遵循该顺序连续奏出；反复回跳或内层反复插入额外小节时
  不能跨越拼接成片段（例如上例中范围 3~7 因内层反复 `|:5 6:|x3` 插入额外的
  5、6 而无匹配，范围 5~6 则能定位到 6 个片段）
- 片段的起止毫秒与时长沿用展开接口的速度与毫秒规则，临时变速按演奏序号生效
- 无匹配时页面明确显示空结果

## 实时节拍器

点击“播放节拍器”后，页面以当前乐谱和临时变速方案调用展开与拍点接口，
从演奏时间 0 毫秒开始发声：每小节首拍为高音（880 Hz），其余拍为低音（440 Hz）。

- 拍点由 Web Audio 音频时钟预排程，滚动按左闭右开的短时间窗（500 毫秒）请求拍点接口
- 按演奏序号与拍序去重，跨窗口与反复回跳不漏拍、不重拍
- 点击“停止”、修改乐谱或临时变速方案时，取消尚未发声的拍点，过期请求的响应不再排程
- 播放到曲终自动停止；接口报错显示在页面上

## 节拍 MIDI 导出

点击页面上的“下载节拍 MIDI”，或调用 `POST /api/midi`（请求体仅需 `input`
与可选的 `tempo`，与展开接口相同），即可按当前输入生成节拍 `.mid` 附件
（`metronome.mid`，MIME `audio/midi`），导入音乐软件后可离线跟随。

- 输出为单轨 SMF 格式 0，分辨率 480 ticks/拍；每拍作为一个四分音符，
  事件位置按**累计拍数 × 480** 直接定位，不经过取整毫秒反推
- 音符写在第 10 通道（打击乐通道）：每小节首拍用 76 号音符，其余拍用 77 号，
  力度 100，每个音符持续 120 ticks
- 在起点（tick 0）及每一处实际发生变化的速度处写入 Set Tempo 事件；
  微秒/拍按 `60000000 / BPM` 四舍五入取整，相同速度不重复写事件
- 速度切换复用反复展开与临时变速优先级（临时变速优先于原谱显式速度，
  未标速小节沿用上一速度）
- 轨道结束（End of Track）位置为全曲拍数 × 480
- 沿用输入错误与 5000 小节限制，并额外限制全曲总拍数不超过 5000；
  速度换算后的微秒/拍无法用 MIDI 三字节正整数（1~16777215，约合 4~120000000 BPM）
  表示时返回可读错误并注明来源（原谱行或“临时变速”方案行）
- 任何校验失败都返回 HTTP 400 与统一结构的 JSON 错误，页面只显示错误而不下载，
  因此不会得到残缺文件

## 校验规则

- 格式错误：定位到具体输入行
- 拍数与 BPM 必须为正整数，错误定位到源行
- 小节编号必须唯一，重复时指出首次出现的行号
- `|:` 与 `:|xN` 必须配对，未配对时定位到对应行
- 展开超过 5000 小节时停止，并指出导致超限的源行
- 节拍点查询的起止毫秒必须为数字，起始不为负且结束大于起始；
  时间窗内拍点超过 5000 时停止，并指出对应源行
- 临时变速方案的演奏序号与 BPM 必须为正整数；序号重复时指出方案内首次出现的行号，
  序号超出展开范围时指出展开后的总小节数；方案错误统一标注“临时变速”及方案内行号
- 片段定位的起止小节编号必须是非负整数且都存在于源谱；
  起点在源谱输入顺序中的位置不得晚于终点
- MIDI 导出沿用以上全部输入与临时变速校验及 5000 小节限制；
  全曲总拍数超过 5000 拍时停止并指出对应源行；速度（初始、原谱或临时变速）
  超出 MIDI 三字节速度可表示范围时，返回可读错误并注明来源行，不生成文件

## 本地开发（不使用 Docker）

```bash
pip install -r requirements.txt
python app.py
```

## 项目结构

```
app.py               Flask 应用与 API（展开、拍点查询、片段定位、MIDI 导出）
repeats.py           反复段解析、校验、展开、排练时间轴、节拍点查询、片段定位与 MIDI 生成
templates/index.html 前端页面（原生 HTML/JavaScript）
requirements.txt     Python 依赖（MIDI 生成仅用标准库，无额外依赖）
Dockerfile           镜像构建（依赖随容器启动安装）
docker-compose.yml   Compose 编排
```
